## Blocking defect: false visitor denominator metadata

The deprecated daily `visitor_attack_rate` is calculated using visitor identities that have arrived by that date:

- `arrived_visitors` is date-specific at [travel.py:2240](/private/tmp/jsy-v11-final-audit/src/jersey_outbreak/travel.py:2240).
- The alias and its truthful replacement both divide by that value at [travel.py:2272](/private/tmp/jsy-v11-final-audit/src/jersey_outbreak/travel.py:2272).

But diagnostics state:

- `visitor_attack_rate_denominator = len(plan.visitor_records)` at [travel.py:2712](/private/tmp/jsy-v11-final-audit/src/jersey_outbreak/travel.py:2712), which is the whole-horizon visitor total.
- The same diagnostics correctly describe the replacement denominator as “arrived visitor identities by date” and map the deprecated alias to that replacement at [travel.py:2715](/private/tmp/jsy-v11-final-audit/src/jersey_outbreak/travel.py:2715).

Read-only reproduction with one visitor arriving on 6 January and one on 8 January produced:

```text
2025-01-06_daily_visitor_arrived_denominator: 1
diagnostics_visitor_attack_rate_denominator_formula_len_visitor_records: 2
visitor_attack_rate_alias_target: 0.0
```

Thus the value and its published diagnostic disagree whenever arrivals are staggered. No test references `visitor_attack_rate_denominator`, so the green suite does not detect this regression. The synthesis requires explicit denominator metadata at [V1_1_SCIENTIFIC_DESIGN_SYNTHESIS.md:55](/private/tmp/jsy-v11-final-audit/docs/research/v1_1/V1_1_SCIENTIFIC_DESIGN_SYNTHESIS.md:55) and makes it an M11-D PASS condition at [V1_1_SCIENTIFIC_DESIGN_SYNTHESIS.md:101](/private/tmp/jsy-v11-final-audit/docs/research/v1_1/V1_1_SCIENTIFIC_DESIGN_SYNTHESIS.md:101). O2 therefore cannot be classified CLOSED.
